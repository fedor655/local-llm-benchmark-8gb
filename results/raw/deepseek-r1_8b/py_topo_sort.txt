Мы будем использовать алгоритм Книга (Kahn) для топологической сортировки.
 Шаги:
 1. Построим граф и вычислим степени (in-degrees) для каждой вершины.
 2. Найдем все вершины с нулевой in-degree и добавим их в очередь.
 3. Будем извлекать вершины из очереди, уменьшать in-degree смежных вершин, и если in-degree становится нулевым, добавляем в очередь.
 4. Если в конце не все вершины были обработаны, то цикл есть -> возвращаем None.
 5. Иначе возвращаем порядок обхода.

 Однако, обратите внимание: граф может быть не связным, но алгоритм Книга все равно должен работать, если нет циклов.

 Важно: граф может иметь несколько компонентов, но если в одном из них цикл, то возвращаем None.

 Реализация:
  - Создадим список (или массив) для графа: graph[i] = список смежных вершин из i.
  - Создадим массив in_degree длиной n, инициализируем нулями.
  - Для каждого ребра (a, b): добавим b в graph[a] (если ребро направлено от a к b) и увеличим in_degree[b] на 1.

 Но в условии ребро (a, b) означает 'a должно идти до b', то есть ребро направлено от a к b.

 Пример: 
   n = 3, edges = [(0,1), (0,2)] 
   Тогда граф: 0 -> [1,2], 1 -> [], 2 -> [].
   in_degree: [0,1,1]

 Однако, обратите внимание: в условии граф может быть не связным, но алгоритм Книга обрабатывает все компоненты, если нет циклов.

 Но есть нюанс: если граф не связный, то алгоритм все равно должен вернуть топосортировку, если нет циклов. 
 Или же если есть несколько компонентов, то топосортировка должна учитывать все вершины.

 В нашем алгоритме мы обрабатываем все вершины с нулевым in-degree, и далее. Если в какой-то компоненте нет циклов, то все вершины должны быть обработаны.

 Однако, если есть цикл, то некоторые вершины не будут обработаны.

 Поэтому условие: если длина topo_order равна n, то возвращаем порядок, иначе None.

 Но есть еще один момент: граф может иметь несколько ребер между одной парой? 
 Условие не запрещает, но тогда in_degree может быть больше 1. Алгоритм это учитывает.

 Также, обратите внимание, что граф может быть направленным, но не обязательно простым (может быть несколько ребер между одной парой). 
 Но условие не говорит, что граф простой. Однако, в топосортировке это не проблема, но тогда in_degree будет больше.

 Но в условии сказано: ребро (a, b) означает 'a должно идти до b'. Это может быть несколько ребер между a и b? Тогда условие выполняется несколько раз, но это не влияет на алгоритм.

 Однако, если граф не простой, то мы должны учесть все ребра. В нашем коде мы просто добавляем все выходящие ребра из a в b.

 Но есть еще один момент: если граф не ориентированный? Нет, условие говорит о ребре (a, b) как направленном.

```python
from collections import deque

def topo_sort(n: int, edges: list[tuple[int, int]]) -> list[int] | None:
    graph = [[] for _ in range(n)]
    in_degree = [0] * n
    
    for a, b in edges:
        graph[a].append(b)
        in_degree[b] += 1
    
    queue = deque()
    for i in range(n):
        if in_degree[i] == 0:
            queue.append(i)
    
    topo_order = []
    while queue:
        node = queue.popleft()
        topo_order.append(node)
        for neighbor in graph[node]:
            in_degree[neighbor] -= 1
            if in_degree[neighbor] == 0:
                queue.append(neighbor)
    
    return topo_order if len(topo_order) == n else None
```
